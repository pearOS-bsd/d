# distnoted

The distributed notification server of pearOS, wire compatible with the `distnoted` of macOS 26.7.2: CoreFoundation's distributed center (`CFNotificationCenterGetDistributedCenter`, `NSDistributedNotificationCenter`) of a Mac program registers, posts and gets its notifications as on the Mac.  Plain C, no Apple header; built on FreeBSD with clang + ld64.lld like `tccd`.  The protocol and the evidence: `research/docs/OPENDIRECTORY-DISTNOTED-WIRE.md`.

- `distnoted agent`: a user's instance, `com.apple.distributed_notifications@Uv3` (job `launchd/com.apple.distnoted.xpc.agent.plist`, `@USER@` = the console user).  `distnoted daemon`: the system instance, `@1v3` for system processes and `@0v3` for the agents (job `launchd/com.apple.distnoted.xpc.daemon.plist`).
- Messages (one-way XPC, `version` 1): `register` (name, object, token, options = suspension behavior in the low 4 bits), `unregister` (tokens), `post` (name, object, userinfo, options 1 DeliverImmediately / 2 PostToAllSessions), `suspend`, `unsuspend`; the server sends `post_token` (token, name, object, userinfo) for every matching registration.
- Apple's rules, taken from the decompiled distnoted: a registration for any name and any object is dropped (unsandboxed clients); a suspended client's posts are held / coalesced / dropped by the registration's behavior and sent at `unsuspend`, a deliver-immediately post goes at once (after the queue); PostToAllSessions goes from the agent to the daemon as `post_all` and to every session from there; the locale and preference names also post their notify(3) names.  With no daemon running an agent delivers PostToAllSessions posts in its own session.
- How the agent and the daemon talk to each other is ours (both ends are ours; Apple's own message between them is not known): the daemon sends a `post_all` back to every agent as a `post`, and an agent introduces itself with `unsuspend`.
- `-v` logs every message; `agent=NAME super=NAME0` / `daemon=NAME1 agents=NAME0` serve other names (tests on a Mac).

Build: `sh build.sh OUTDIR` (FreeBSD: llvm21; elsewhere `CC=clang LD64=ld64.lld sh build.sh OUTDIR`).

Tested on the Mac VM: Apple's CoreFoundation and Foundation against this daemon (jobs `com.pearos.t.dn` agent and `com.pearos.t.dnd` daemon, names redirected with `research/tools/opendirectory/odcap.dylib`, probes `dnt` and `dnt2`) give the same deliveries as Apple's distnoted for the same runs (two registrations of one process, a specific object, an all-names registration, suspension with coalesce, PostToAllSessions through the daemon, userInfo with numbers and data).  On the FreeBSD lab VM (darwinator): our launchd starts the agent and the daemon on demand and the Mac's CoreFoundation/Foundation (dyld cache) get the same deliveries, PostToAllSessions included.
